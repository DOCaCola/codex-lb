# Design

## Contracts

`input_tokens` is inclusive of uncached input, cache reads and cache writes. `output_tokens` includes thinking. Reported cache-write and reasoning detail is nullable when absent. A stream starts its monotonic timer immediately before each physical upstream open; first output is the first nonempty generated text/thinking/tool payload, not transport or metadata frames. Terminal, failure and close paths finalize duration; TTFT remains unknown without generated content.

Price each input category once. An incomplete price is unknown, including for API-key cost settlement; an explicitly zero rate is free. Claude prices represent API-equivalent estimates, never subscription billing. Existing historical rows remain untouched when detail cannot be recovered.

Import the Claude 1-hour cache-write field actually published by LiteLLM (`cache_creation_input_token_cost_above_1hr`) and the corresponding explicit >200k context variants. One shared cost calculation applies the context threshold to inclusive input and prices uncached input, cache reads, 5-minute writes, 1-hour writes and output exactly once. A selected tier with incomplete relevant rates is unknown, not priced at the base tier. Operator-authored source prices (generic OpenAI-compatible sources) remain explicit and win for those sources. Claude source rows are not operator-authored: they are read-only, and their flat rates are a projection-time copy of the same catalog that lacks cache-write and long-context rates, so Claude costs always use the live catalog calculation. Persisted totals, request detail and settlement use the same result.

On an unpriced completed request, cost-limited API-key reservations settle at the admission reserve estimate rather than releasing or zero-debiting that limit. The request log retains null cost. This is a nonzero estimated limit debit, not a provider invoice or a claim of exact cost; it can be lower than actual API-equivalent cost. Historical Claude rows are excluded from generic calculated-cost backfill and lack provenance, so legacy stored zero is presented as unknown without changing the row. New rows mark API-equivalent or unpriced provenance. Request-detail components are shown only if the current catalog calculation agrees with the persisted estimate.

Known Claude 4.5 Sonnet/Haiku use budget thinking; explicitly configured later families use adaptive thinking. Low/medium/high/max map to 4096/8192/16384/32000 budget tokens. A budget must be at least 1024 and below the effective max output tokens, preserving explicit caller caps. Unsupported combinations fail before dispatch.

Translated thinking rejects unsupported temperature/top-p combinations before upstream dispatch; native Messages keeps caller controls and records its effective upstream thinking and effort without fabricating an effort from a budget. The request log separates requested effort from effective upstream effort, mode and budget, including API-key policy and retry normalization. "Effective" means what was sent upstream. An absent `thinking` block runs adaptive thinking on Opus 5/5.5, Sonnet 5/5.5 and Fable but no thinking on Opus 4.6-4.8 and Haiku, and the effort default is `medium` on Opus 5.5 versus `high` elsewhere (Anthropic API reference cached 2026-09-25). Recording a guessed value would drift with each model, so both stay NULL when left to the default; `disabled` is recorded only when explicitly sent, which gives "off" a single spelling.

Cost provenance is scoped by provider identity. Only legacy native-Claude rows without provenance become unknown; another source using an `anthropic/claude-*` model alias keeps its valid cost. Aggregate cost is a known monetary subtotal plus request-grain coverage counts: priced (including explicit free), unpriced (usage known, price unavailable), and unmetered (usage unavailable). Legitimate no-generation local refusals are outside cost-coverage population. A partial subtotal is always labelled incomplete, not total spend or dollar coverage. Durable rollups carry the same classification through retention, reconciliation and deletion. Historical coverage is derived only from retained rows; when source rows are gone, coverage is unknown rather than presumed complete. The API-key reservation estimate remains separate from report cost and is not a guaranteed hard-dollar cap.

The API-key seven-day totals, account buckets, hourly trend points, dashboard overview cost card and its previous-window comparison, usage summary and fleet pressure windows carry the same coverage counts, and their raw tails use the same known-cost expression as the folds so a window reports the same subtotal before and after folding. The dashboard cost card withholds its per-hour average and period comparison while coverage is incomplete. A historical bucket with a known subtotal but unavailable coverage displays that subtotal as known with coverage unavailable; `Unknown` is reserved for no known cost at all. Cost charts are known-subtotal charts when any bucket is incomplete. Request-log conversation summaries, conversation listings and model-level details use the same classifier, including explicit-zero prices and dispatched failures. Historical rollup rows begin with unknown coverage; bounded repair only clears it for fully retained windows or lifetime rows whose retained request count matches the existing folded count.

## Reference evidence

Inspected 2026-09-29 snapshots: OpenCodex `8a005dd98ff12cdc000c6f4961cbf71a592d6b6b` records Haiku 4.5 adaptive rejection/budget acceptance and inclusive cache accounting; Sub2API `9a62841fd124d026cf3694fcf9b79e98addcdbdc` separates 5m/1h cache creation and first-token/total duration; CLIProxyAPI `d33f63f8e3d98428440ebca5a5b6a981a61ff71e` preserves cache and optional reasoning detail. These are source and local-test evidence, not independently verified subscription invoices.

Price-override precedence (source inspection of shallow clones, 2026-09-29; not runtime-verified): Sub2API `a60a29549f488a854966aaec9541abbe006cac22` (`backend/internal/service/model_pricing_resolver.go`) resolves group → channel → LiteLLM → fallback and applies overrides per field on a cloned LiteLLM base, with separate 5m/1h cache-write prices and long-context ladders kept from the official base. Its channel prices are operator resale billing, not API-equivalent estimates. OmniRoute `666ea59b4c5980062c4012ee9228135ee4dd8989` (`src/lib/db/settings/pricing.ts`) merges defaults → LiteLLM → models.dev → user per field (object spread per provider/model) and exposes a per-model source map. OpenCodex `8a005dd98ff12cdc000c6f4961cbf71a592d6b6b` (`src/usage/user-cost-overlays.ts`) accepts whole four-field display-only overlays that beat the built-in catalogs, and treats an all-zero overlay as fall-through, which conflicts with codex-lb's explicit-zero-is-free rule. CLIProxyAPI `a270e7b9e57aaecd8f82555f44c2108518ad2330` has no pricing code. If Claude price overrides are ever added, the fitting model is the Sub2API/OmniRoute one: nullable per-field overrides that inherit catalog values (including cache-write and long-context rates), with provenance for each price. The projected snapshot columns would then be replaced, not reinterpreted as overrides. Pricing source is the existing models.dev/LiteLLM snapshot feed, with explicit aliases for dated model IDs.
