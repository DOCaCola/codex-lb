# Claude Chat adaptation context

## Protocol and ownership

Chat clients submit portable messages. The gateway converts these to Responses input, then the existing Claude projection sends Anthropic Messages over the enrolled OAuth account. The Responses `SourceDispatch` owner takes the sole bulkhead claim and API-key reservation and performs the existing auth/quota/overload recovery. A Chat output adapter inside that owner emits JSON or SSE and classifies stream terminal frames for settlement. Post-open transport errors become Chat SSE errors; pre-open refusals keep the source status and retry headers.

For example, a Chat request with `max_completion_tokens: 17`, `stop: ["END"]` and a `lookup` function declaration sends Claude `max_tokens: 17`, `stop_sequences: ["END"]` and the existing reversible tool declaration. Signed thinking and search state remain Responses-native account-bound objects; Chat `reasoning_content` is plaintext, even when resent. Active reasoning with tools uses a unique authenticated, same-key/conversation/model/account replay record matching the entire canonical visible prefix and all tool results. The private record stores both the projected input actually sent to Claude and the canonical Chat input used for matching later turns. Anonymous or unavailable signed replay reconstructs the affected tool cycle as ordinary assistant text and quoted user results, preserving visible content but not native tool-use semantics. Adaptive-capable reasoning asks Claude for summarized display unless the caller hides it.

## Reference evidence

Source snapshots inspected during the preceding investigation on 2026-09-29: OpenCodex `8a005dd98` (Chat-to-Responses routing and incomplete-status policy), Sub2API `9a62841fd` (Chat-to-Responses-to-Messages and OAuth preparation), CLIProxyAPI `d33f63f8` and OmniRoute `113de57b` (direct Chat/Messages stop, tool and reasoning translation). OpenCodex commit `3fe2e371507138e1c3f43b486ef77bb143440abf` (2026-09-26) documents signature-only Claude streams when adaptive thinking omits display; its Anthropic adapter requests `display: "summarized"` unless the caller hides thinking. These are source-design references, not live OAuth qualification or dependencies. This implementation uses local synthetic credentials and upstream stubs for verification; it does not copy reference code.

OpenCodex bridges non-`openai-chat` Chat requests through Responses and preserves plaintext reasoning without signing it; its Anthropic adapter restores only genuine signatures. Sub2API's Anthropic-platform Chat handler also routes Chat through Responses to Messages. It first wraps Chat `ReasoningContent` in textual `<thinking>` within an assistant output item, while its Anthropic reverse conversion restores only marked genuine encrypted thinking envelopes and skips plain unsigned reasoning. CLIProxyAPI either omits unsigned thinking or uses an empty signature in compatibility mode. OmniRoute inserts a fabricated redacted placeholder for an active thinking/tool cycle; this implementation deliberately does not copy that behavior. None of these source inspections is a live Claude OAuth qualification result.
